# Stage 2 API

The Stage 1 API is intentionally small. It proves that the browser, REST service, migration layer, and PostgreSQL are connected before product workflows are added.

Stage 2 adds session-based authentication and role boundaries while keeping the public platform status endpoint.

## `GET /actuator/health`

Spring Boot Actuator health endpoint. The response is suitable for local and deployment health checks.

Example:

```json
{
  "status": "UP",
  "components": {
    "db": {
      "status": "UP"
    }
  }
}
```

## `GET /api/v1/platform`

Returns the database-backed foundation status.

Example:

```json
{
  "service": "startup-investment-platform-api",
  "stage": "foundation",
  "database": "connected",
  "migrationVersion": "1",
  "checkedAt": "2026-10-22T17:00:00Z"
}
```

The `checkedAt` value is generated by the backend. `migrationVersion` comes from the `platform_metadata` table created by Flyway.

## Authentication endpoints

### `GET /api/v1/auth/csrf`

Creates or returns the CSRF token held by the current browser session.

```json
{
  "token": "session-scoped-token"
}
```

State-changing requests under `/api/v1/` must send the token in `X-CSRF-Token`.

### `POST /api/v1/auth/register`

Creates a `STARTUP` or `INVESTOR` account, establishes the session, and returns the authenticated user.

```json
{
  "email": "founder@example.com",
  "password": "at-least-12-characters",
  "role": "STARTUP"
}
```

`ADMIN` is rejected for public registration. Duplicate normalized email addresses return `409 Conflict`.

### `POST /api/v1/auth/login`

Authenticates an existing account and establishes the HttpOnly session cookie.

```json
{
  "email": "founder@example.com",
  "password": "at-least-12-characters"
}
```

Incorrect credentials return the same `401` shape whether or not the email exists.

### `POST /api/v1/auth/logout`

Invalidates the current session and returns `204 No Content`. The request must include a valid CSRF token.

### `GET /api/v1/me`

Returns the authenticated session user. Without a session, returns `401`:

```json
{
  "code": "UNAUTHENTICATED",
  "message": "Authentication required."
}
```

### Role boundary smoke endpoints

These small endpoints make backend authorization testable before domain workflows arrive:

```text
GET /api/v1/startup/access   STARTUP only
GET /api/v1/investor/access  INVESTOR only
GET /api/v1/admin/access     ADMIN only
```

## Errors

Malformed requests are returned as JSON with a stable `code`, `message`, and optional `fieldErrors` object. Unhandled server failures are not returned with stack traces or database credentials.

## Compatibility and CORS

The backend permits the configured `FRONTEND_ORIGIN` for local development and allows credentials for the HttpOnly session cookie. Authentication and authorization are enforced for the Stage 2 protected endpoints.

## Postman

Import [`docs/postman/stage-2-authentication.postman_collection.json`](postman/stage-2-authentication.postman_collection.json) into Postman to run the foundation and authentication smoke requests. Change the `baseUrl` collection variable for a non-default backend port.
